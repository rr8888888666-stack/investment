# 锐思投研 · A股研究工作台

一个**真实可用**的本地投研平台：真实数据源、本地持久化、每日自动更新、可录入自己的持仓与自选。

不是单文件 demo —— 数据不写死在页面里，而是每天从数据源同步进本机数据库，页面从接口读取。

---

## 快速开始

```bash
cd ruisi-platform

# 首次：同步数据（约 2 分钟，29 个任务）
python3 sync.py --with-financial

# 启动服务
./run.sh            # 或 python3 server.py
```

浏览器打开 **http://127.0.0.1:8770**

`./run.sh --sync` 可以先同步再启动。

> 零第三方依赖，Python 3.7+ 标准库即可运行（`sqlite3` + `http.server`）。

## 架构

```
NeoData（腾讯金融数据服务）
      │  sync.py 按 29 个任务拉取
      ▼
data/market.db  （SQLite：14 张表，含原始返回留档）
      │  server.py 只读 API
      ▼
web/  （前端，全部数据经 /api/* 读取）
```

| 文件 | 作用 |
|---|---|
| `db.py` | 库结构与 helper |
| `neodata.py` | NeoData 客户端 + markdown 表格解析（带退避重试） |
| `sync.py` | 数据同步，幂等，可按任务/日期执行 |
| `server.py` | 本地 HTTP 服务 + REST API + 按需补齐 |
| `web/` | 前端（五模块） |
| `verify_sync.py` | 同步层验证（空召回重试、派生字段、异常传播） |
| `verify_e2e.py` | 端到端验证（接口 / 数值 / 写回环 / 安全 / 库内一致性） |
| `verify_frontend.js` | 前端渲染验证（jsdom 装页面 + 真实 HTTP 打本机服务） |
| `data/market.db` | 你的数据，全部留在本机 |

## 数据血缘

每个数字都能通过 `raw_recall` 表回到它的原始 API 返回。

| 字段 | 来源接口 | 时效 |
|---|---|---|
| 指数 / 个股 / 板块行情 | 统一行情查询 | 实时 |
| 板块资金排行、涨股比、领涨股 | 板块资金排行 | 实时 |
| 板块涨跌排行 | 板块涨跌排行 | 实时 |
| 两市成交量额 | 大盘市场宽度统计 | 实时 |
| 个股主力/散户/超大单资金流 | 统一资金流向 | 实时 |
| 个股 PE / PS / PCF / PEG 序列 | 统一估值查询 | **T+1** |
| 指数 PE / PB 序列 | 指数估值 | 实时 |
| 财务（营收、利润、每股净资产、ROE） | 综合财务指标 / 利润表 | H+1 |
| 分红派息明细 | 分红派息详细 | T+1 |
| 总市值 / 流通市值 | A股个股交易排行榜 | 实时 |

### 三处推算（都会在界面标注口径）

1. **PB** = 最新收盘价 ÷ 最新一期每股净资产
2. **股息率（TTM）** = 近 12 个月已实施派息合计 ÷ 最新收盘价
3. **PE 分位** = 当前 PE 在库内估值序列中的位置（**样本只有十几个交易日，不等于长周期分位**，界面明确标注了窗口）

> 这三处都用「最新」口径，所以**只写在最新那一行上**，不写进历史行。
> 否则序列图上会变成一条水平线，看着像「历史股息率一直没变」——那是误导。

## 空召回自动换问法

上游是按**自然语言**检索的，同一意图换个措辞，命中率不同。实测连续跑同步时，
每十几轮就会有一轮某任务空召回（当天那块数据就缺了）。

因此每个同步任务都配了 2 个**备用问法**，主问法空召回时自动依次重试；
血缘表里记的是**真正命中的那个问法**，所以溯源不会指到一个查不到数据的 query。
全部问法都没命中才报失败，并在 note 里写明试了几种。

`verify_sync.py` 会断言**每个任务都配了备用问法**，防止以后新增任务时漏配。

## 运行中发现并修掉的问题（都有测试守着）

| 问题 | 后果 | 现在的做法 |
|---|---|---|
| 空召回没有重试 | 该任务当天数据缺失，且被算作「失败」而非修复 | 备用问法自动重试 |
| **召回到内容但写入 0 行被静默算成功** | `ok_count` 虚高 ——「31/31 成功」其实一个数都没写进去 | 显式报错，note 里带上 `api_type` |
| **股息率被写到该股全部历史估值行** | 序列变成水平线，将来画图会被误读 | 先清空再只写最新行 |
| 单独跑 `--only valuation` 后股息率留在旧行 | 最新一行反而显示「—」 | 估值任务也会触发股息率重算 |
| **调用方传的 name 被直接写进行情/估值表** | 打错字或传占位符，整站都显示错名字 | 向数据源确认权威名称；只给 code 时也从数据源回填 |
| 定时任务定在 15:30 | 实测 15:31 拿到的是**前一日**数据（上游发布有延迟），要靠补跑纠正 | 改到 16:30 |

## 数据边界（重要，请先读）

这个平台的价值一半在于**明确知道什么拿不到**。以下缺口是上游接口的真实限制，不是没做：

| 缺口 | 原因 | 平台的处理 |
|---|---|---|
| 涨跌家数 / 涨停家数 | 上游接口不提供该字段 | **不展示**。也不用其它口径估算 —— 用 3 个行业去冒充全市场家数，比缺数据更糟 |
| 全部申万一级行业 | 排行接口单次仅返回前 3 / 前 6 名 | 只展示取到的板块，并标注「非全部行业」 |
| 全市场估值 | 估值接口是单标的粒度，无法批量 | 覆盖重点研究池 + 自选股；选股器实时显示「估值覆盖 N/M」 |
| 条件选股 | 上游没有筛选接口 | 选股器在本地库上执行，只能在已入库标的中筛选 |
| 长周期估值分位 | 单次仅返回约 11 个交易日 | 分位标注真实窗口长度，不包装成「十年分位」 |

界面「市场总览」底部有专门的**缺失数据说明**区块，每次打开都能看到。

## 时效性

- 这是**同步快照**，不是逐笔实时推送。页面在两次同步之间不会变化。
- 顶部标识显示数据时点；悬浮可见精确抓取时间。
- 交易类数据为「实时」时效接口 → 同步到当日收盘值。
- 估值序列为 T+1 → 最新一行通常是**前一交易日**（界面的估值序列图会体现）。

要更新数据：

```bash
python3 sync.py                    # 同步当日
python3 sync.py --with-financial    # 连财务一起重取
python3 sync.py --only indices,sectors
python3 sync.py --date 2026-09-18
python3 sync.py --list              # 查看全部任务
```

日常只需跑一次不带参数的 `sync.py`：财务数据 7 天内不会重复拉取（财报是 H+1 时效，没必要每天取），约 1.5 分钟。

## 功能

**市场总览** — 8 大指数 + 两市成交 + 行业板块一览 + 行业涨跌幅/资金图 + 全池个股表
**个股深度研究** — 8 只重点标的（覆盖价值/成长/AI算力/金融/保险/公用/资源），含行情、估值与分位、PE 序列图、资金流、财务
**选股器** — 8 个条件 + 估值覆盖提示，在本地库上执行，结果可一键加自选
**持仓与自选** — 录入真实持仓，自动算市值/盈亏/权重，机械式计算集中度风险
**数据血缘** — 库表行数 + 最近 100 条原始 API 返回

自选股和持仓数据存在 `data/market.db`，**不上传任何地方**，服务只监听 `127.0.0.1`。

### 按需补齐

加入一只库里没有的标的时，服务会**立即**抓取它的行情、估值、财务、分红，而不是等下一次全量同步。这是自选池能随意扩展的原因。

## 验证

三套都是可重复执行的脚本，当前全绿：**同步层 13/13、端到端 86/86、前端渲染 60/60**。

```bash
# 1) 同步层：不联网，守空召回重试 / 派生字段口径 / 异常传播
python3 verify_sync.py

# 2) 端到端：接口结构、关键数值、写入回环、安全性、库内一致性
python3 server.py &
python3 verify_e2e.py

# 3) 前端渲染：把页面装进 jsdom，用真实 HTTP 打本机服务
#    需要 jsdom：npm install jsdom
node verify_frontend.js
```

**这三套都不硬编码某一天的数字** —— 期望值一律从接口/库里推导。这不是洁癖：
第一版是照着交付当天的快照写的，第二天数据一更新就整片失败（76 项里挂 15 项），
那种「验证」等于没有，还会把真实回归淹没在噪声里。

覆盖范围：

- `verify_sync.py`：备用问法覆盖率、空召回自动改问法（含血缘记录的是命中问法）、
  全空时明确报错、空写入不算成功、网络异常仍向上抛、股息率只写最新行
- `verify_e2e.py`：接口结构与数值、写接口回环、非法入参拒绝、目录穿越拦截、
  红涨绿跌配色、以及**库内一致性**（页面上的数字必须能从库里 SQL 算出来）
- `verify_frontend.js`：不 mock 数据，用真实 HTTP 打本机服务，检查五个模块是否真的渲染出来。
  开头清空自选与持仓、结尾清理，可重复执行

> 两个脚本都会动态挑一个库内尚无数据的标的来验证「按需补齐」路径，因此每次跑都会真实调用上游接口。
> **三套不要并发跑** —— 都会增删持仓/自选，会互相踩库。
